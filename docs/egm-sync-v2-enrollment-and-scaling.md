# HiMemo v2 の管理者端末登録と長期保存

## 現在のQR対応と将来の相互承認

2026-11-16の実装は、既存のSYNC/ADMIN復旧コードを役割別QRとして表示・読み取る方式である。QR自体が秘密情報を含み、撮影したコピーからも復旧できる。有効期限や一回限りの承認は付かない。この制約を画面で伝え、既存のアカウント・世代・登録情報の検証を維持する。

以下の一時鍵、期限、相互承認による方式は将来案であり、現在の復旧QR方式とは別のプロトコルとして設計・レビューする。

## 管理者端末の登録（将来案）

新端末では、管理者登録済みの端末から QR で承認を受けるか、管理者復旧コードを入力する。QR 登録は既存端末が使える場合の日常の経路とし、復旧コードは既存端末が使えない場合にも使える。通常同期への参加と個別パスフレーズによる解除は、それぞれ独立した権限とする。

1. 新端末は端末登録用の一時鍵ペアを作る。公開鍵、ランダムな要求 ID、有効期限、プロトコル版を含む QR を表示する。
2. 登録済み端末で読み取り、管理者の再認証を行う。両端末で、アカウント・世代・要求・一時鍵に結び付いた確認表示を照合し、利用者が承認する。
3. 登録済み端末は管理者鍵を新端末の一時公開鍵宛てに認証付きで暗号化する。受け渡しの経路には暗号文を渡す。新端末は対応する未使用の要求であることを確認し、登録を確定する。期限切れ、再利用、対象の取り違え、取消しは拒否する。
4. 新端末は管理者鍵を端末認証付きで保管し、一時鍵を破棄する。今後の管理者モード開始には再認証を求める。

QR の中身は登録要求と公開鍵で構成する。QR の撮影だけで管理者鍵を入手したり、承認済みの要求を使い直したりできないことを試験する。鍵転送の候補は HPKE とし、ペアリング相手の確認と再利用防止を含む方式は実装前に別途レビューする。既に管理者鍵を取得した端末から権限を取り消す場合は、その端末が持つ過去の鍵と暗号文も考慮して鍵更新の範囲を決める。

## 増え続けるメモの保存

2026-11-15 時点では、先行して同期用復旧コードによる通常プロファイルの登録・復旧を実装した。アカウントの固定登録情報は作成専用で、クラウドへの保存・読み戻し・復号・アカウントの再照合が済んでから端末内へ保存する。同期コードに管理者鍵は含めない。空の世代の登録を検証するサービスであり、旧 ZIP の一括移行の公開確定処理、管理者用復旧コード、QR 承認、生体認証で守る管理者鍵保存はまだ提供していない。これらを接続するまで通常画面からの利用は有効にしない。

| 処理 | 読む範囲 | 方針 |
| --- | --- | --- |
| 一覧を開く | 選択プロファイルの表示範囲と前後のページ | プロファイルと記録日の月を論理区画にする。月内もページ取得し、本文と添付は必要になってから開く |
| 検索する | 解除中の対象プロファイルと指定期間 | 暗号化したプロファイル別索引を使う。全期間指定時は区画を順に検索して結果を逐次返す。未取得区画があれば検索範囲を明示する |
| 同期する | 前回以降に変更された記録と必要な添付 | クラウドの差分トークンと変更 ID を使う。古い日記の編集も新しい変更として送受信する |
| 空き容量を確保する | 古く、別の保存先で復元可能と確認した暗号文 | 端末の暗号文キャッシュを整理する。未送信、競合、復元未検証のデータは対象から除外する |

日記の記録日と、同期上の変更順を別に持つ。記録日を修正した場合は、同じメモ ID のまま一覧と索引の所属区画を更新する。時系列の表示順には安定した ID を同順位の比較に使う。添付を遅延取得し、オフラインで残したい期間は端末に保持できる設計とする。クラウド同期なしの端末では、元データの唯一のコピーを容量整理の対象から除外する。

初版は単一のローカル DB に論理区画とページ取得を導入する。月ごとの物理ファイル分割は、測定で必要性が分かってから検討する。検索索引、見出し、スニペット、私用メモの記録日と所属区画はプロファイル鍵で保護し、再ロック後も平文が DB、WAL、一時ファイル、OS 検索に残らないことを確認する。検索索引の実装候補は、区画ごとの暗号化索引を必要な分だけ開く方式と、ページ単位で暗号化する検索用 DB。

## クラウド履歴の長期化

端末のキャッシュ整理と、クラウドの履歴圧縮は別の処理とする。初版では差分取得とページ単位の再開を先に検証する。長期運用向けには、プロファイル・期間ごとの暗号化チェックポイントを候補とする。新端末は確定済みチェックポイントと、その後の変更から復元する。クラウドの変更トークンが失効した場合も、この経路で再開できるようにする。

履歴削除の導入条件は、チェックポイントから本文・添付・未解決競合・削除状態を再構築できること、長期オフライン端末からの再接続で古い内容が復活しないこと、復元中の端末が参照している添付を消さないこと。共有添付の回収条件もこの段階で決める。

## 検証順序

- QR 登録と復旧コードでの登録を iPad で試す。取消し、期限切れ、QR の差し替え、同じ要求の再送も確認する。
- 複数年分のメモと添付を使って、最初の一覧表示、期間検索、全期間検索、変更なし同期、過去のメモ一件を編集した同期を測る。取得件数、通信量、応答時間、メモリ使用量を記録し、物理分割の判断に使う。
- 旧 ZIP の復元試験では、複数プロファイルの復元先、古い期間の検索、添付の復元を確認する。既知の写真参照欠落は事前に表示する。
