# HiMemo 同期 v2 設計

実装は `feature/sync-v2` で進める。初期検証は iPad と iCloud を対象にする。Google Drive と Web は、同じデータ規則で鍵保護と差分取得を検証した後に v2 の提供範囲を決める。

[暗号化とロックの設計](egm-sync-v2-security-design.md)

時系列の区画、端末の容量整理、長期の履歴圧縮は [管理者端末登録と長期保存](egm-sync-v2-enrollment-and-scaling.md) に記載する。

## iCloud 初版の利用フロー（2026-11-15 実装）

iOS の設定にある「iCloud 同期 v2」から、独立した暗号化ワークスペースを開く。旧メモ DB と v2 ログを二重書きせず、既存のメモや旧クラウド領域は保持する。v2 選択後の通常起動は v2 ワークスペースへ進む。従来のメモへ戻る操作では、切り替える前の同期先も復元する。

1. 新規登録ではFace ID／Touch IDを標準にし、長い管理パスワードを必須にしない。生体認証を使わない場合の管理パスワードは6文字以上とする。SYNC と ADMIN の復旧コードを別々に保管する。両方の保存確認を行ってからクラウドへ登録する。コードを保管するために別アプリへ移っても、元の認証方式で同じ登録を続けられる。表示中の登録を取り消す導線も用意する。送信済みの保留登録は消さず、再開または勝った世代の復旧コードで解決する。
2. 別端末は SYNC コードで参加する。管理者として使う場合は ADMIN コードを検証し、その端末の管理パスワードを設定する。通常プロファイルの鍵は、検証済みの暗号化登録情報を端末内へキャッシュし、オフラインでも復元できる。
3. 通常メモの作成・編集・削除、私用プロファイルの作成と同じパスワードに一致する全プロファイルの解除、管理者による一括解除を行える。私用の表示名はプロファイル鍵でも暗号化する。管理者・私用パスワードには永続的な試行制限がある。バックグラウンド、手動ロック、画面からの退出時に私用鍵・管理者鍵と画面上の本文を破棄する。v2 の画面の存続中は、旧プロファイルとは独立してネイティブのプライバシー保護を有効にする。
4. 添付は最大64MiB、1MiB単位で暗号化して保存・送受信する。全チャンクと参照元メモを同じトランザクションでキューに入れる。v2 の送信は隔離がある間停止し、明示的な再送では失敗したチャンクを参照元より前へ戻す。ダウンロードでは番号・総数・サイズ・ダイジェストを照合する。ファイルの保存は利用者の明示操作で行い、ネイティブへ渡す名前は basename にする。
5. 旧 ZIP は件数と添付欠落を確認し、私用の各復元先を明示的に選んで取り込む。主操作は「管理者として一括復元・上書き」とし、管理者認証後は私用の復元先を自動作成・再利用する。個別パスワード入力、手動割り当て、未連携添付の個別チェックは要求しない。同じ取り込み元IDのメモはZIPの内容で更新し、既知の競合・削除も上書きする。ZIPに含まれないメモは保持する。手動割り当て方式も副操作として残す。通常メモは通常の復元先にだけ割り当てる。展開・検査・圧縮は別 isolate で実行し、メモ・添付・送信キューは一つの DB トランザクションで確定する。同じ ZIP の再試行では重複しない。明示的な書き出しは選択中の解除済みプロファイルだけを対象にする。ブロック付きメモを編集した場合も、書き出して戻した際に古い本文や削除した添付を再表示しない。
6. メモの競合は全ての版を表示し、利用者が採用する版または削除を明示する。パスワードの同時変更は対象のプロファイルだけを保留し、管理者が全ての鍵・名前の一致を確認して新しいパスワードへ解決する。取得待ちと隔離一覧では再取得・再送を行える。
7. ウィジェット・共有入力は v2 選択中には通常プロファイルへ保存する。元の共有データを確認済みにするのは確定後だけで、同じ要求の再送は既存の編集・削除を上書きしない。v2 の私用メモを Spotlight やウィジェットへ公開しない。

初版は iOS/iCloud を対象にする。管理者鍵は端末限定・端末パスコード設定必須のKeychainに現在の生体登録セットで保護する。管理者認証は生体認証、任意の6文字以上のパスワード、ADMIN復旧コードに対応する。生体認証の再登録や端末交換時はADMINコードからその端末で生体認証を設定する。端末パスコードへの暗黙の切替は行わない。QRペアリングは未対応。通常の編集画面はテキストと添付を扱い、旧ブロックの文字と添付を保ちながらこの形式へ編集する。期間別索引・暗号化検索・長期履歴圧縮・Web/Google Drive の v2 対応は別の拡張範囲とする。

実装の結合試験は独立した二つの DB・鍵ストアとテスト用転送先で行う。iOS の実機用試験にも登録、通常メモ、私用鍵の配信・解除、複数チャンク添付、再取得を接続した。ただし、この Windows ホストでは Xcode/iOS を実行できないため、実 CloudKit と二台の物理端末の確認は未実施。公開前の確認項目は [受け入れ手順](../internal-docs/sync-v2-acceptance.md) にまとめる。

プレビュー期間を利用して、旧クラウド履歴と分離した同期形式へ移行する。手元にあるプレーン ZIP から、メモと添付を復元できることを移行の前提にする。

## 同期

- 通常同期ではプロファイル鍵を要求しない。編集時に本文と添付をプロファイル鍵で暗号化し、送信キューには再利用できる暗号文と変更記録を保存する。受信側も暗号文のまま保存する。鍵は表示、編集、本文を見比べる競合解決に使う。
- 同期鍵で認証付き暗号化した小さな変更ヘッダーに、ランダムなプロファイル ID、メモ ID、変更 ID、親リビジョン、操作種別と暗号文への参照を持たせる。初版では同期先の差分列挙を使ってヘッダーを取得し、既知の変更を除いて新しい暗号文だけを取得する。プロファイル別索引は取得コストを測った後に判断する。
- 変更記録は追記型とし、送信再試行は同じ変更 ID を使う。同じ親から分岐した編集は両方を保存し、削除も変更記録として扱う。端末時刻で勝敗を決めない。暗号文のハッシュは同じ暗号文の識別に使い、本文の同一性判定や HMAC は初版の要件から外す。
- ヘッダーと暗号文の対応、添付参照、保存後の取得位置を検証する。暗号文とローカル適用記録は途中で中断されても再処理できるようにする。添付は参照を公開する前にアップロードする。履歴の圧縮・削除は初版では行わない。

## プレビュー版からの移行

- v2 を別のクラウド領域または世代で開始する。旧バンドルの再生や旧データの削除は移行作業に含めない。旧アプリの端末は v2 に書き込めないようにする。
- 設定に「旧形式の ZIP をインポート」を残す。既存の ZIP デコーダーを再利用し、復元処理は v2 専用にする。復元前にメモ・添付・対象プロファイルを確認する。旧形式の本文は端末上で新形式に暗号化する。プライベートメモはユーザーが明示的に選んで解除した復元先へ入れる。復元先が解決できないデータは通常プロファイルに流さず、対象を報告する。
- 既知の通常プロファイル ID と旧形式のプライベート ID を明示的に識別する。不明な ID は復元前にエラーにする。異なる私用プロファイルはそれぞれ別の復元先に対応させる。復元先が解除されるまでは件数だけを表示し、本文やタイトルをログへ出さない。
- 手元の書き出しを一台で復元して v2 の初期データを作り、ほかの端末は v2 から受信する。復元前に空の復元先を確認する。再試行時に重複しないよう、復元元 ID と復元先の対応を保存する。復元の確定前に同期へ公開しない。
- 提供されたプレーン ZIP v1 の読み取り検査では、通常プロファイルと私用3プロファイルに計54件のメモがあり、添付ファイル34点の参照と ZIP の整合性を確認した。8件のメモにファイル参照が空の写真項目がある。元端末と対象プロファイルの一覧を照合し、別端末で本文と通常・ブロック内添付を開いて確認する。元データがなければ、確認済みの復元範囲は ZIP 内に限る。

## 実装順序

- まず変更履歴の判定を実装し、親子が逆順で到着しても同じ結果になることをテストする。次に認証済みヘッダーの保存、鍵管理、受信と送信の永続化を接続する。実機で隔離を確認した v2 の CloudKit 領域に接続し、旧 ZIP の専用復元から二台目での再取得までを検証する。
- 新端末がロック中でも暗号文を取得できる同期鍵の準備と、プロファイルを開くための鍵の復元を別々に検証する。
- 端末の再インストール、同時編集、削除との競合、添付送信の途中中断、同じ ZIP の再試行を受け入れテストに含める。

## 実装状況

- 変更履歴の判定を実装した。入力は認証済みの単一世代の変更ヘッダーとし、適用可能な最新版の集合と、祖先の到着を待つ変更の集合を返す。本文鍵は使わない。親子の逆順、再送、削除と編集の競合、複数の親を指定した競合解決、不正な履歴をテストする。[判定処理](../lib/features/sync/data/sync_v2_history.dart) · [テスト](../test/sync_v2_history_test.dart)
- 変更ヘッダーを同期鍵で認証付き暗号化する。世代とレコード ID を認証対象に含め、別レコードへの差し替えを拒む。[変更ヘッダー](../lib/features/sync/data/sync_v2_header_codec.dart)
- v2 専用 SQLite に受信ヘッダーと取得位置を一つのトランザクションで保存する。取得位置はヘッダーを受信箱に入れた地点を表す。本文を保存済みかどうかは別に確認する。本文暗号文は同期鍵で認証したダイジェストを検証してから保存する。[受信箱と送信キュー](../lib/features/sync/data/sync_v2_inbox.dart) · [受信処理](../lib/features/sync/data/sync_v2_receiver.dart)
- 編集時に本文をプロファイル鍵で暗号化し、元の暗号文を送信キューに保存する。応答が消失しても再送は同じレコード ID と暗号文を使う。受信と送信はテスト用の転送先で検証した。[本文暗号化](../lib/features/sync/data/sync_v2_payload_codec.dart) · [送信処理](../lib/features/sync/data/sync_v2_publisher.dart)
- 個別パスフレーズと管理者鍵による二つの鍵ラップを実装した。同じパスフレーズで複数の鍵が開くことをテストした。上記の利用フローで画面上の解除セッションとパスワードによる管理者登録へ接続した。QRは別の拡張範囲とし、生体認証は上記のKeychain保護へ接続した。[鍵ラップ](../lib/features/security/data/sync_v2_profile_keys.dart)
- 旧 ZIP の形式・添付参照・復元先検査に加え、再暗号化、添付保存、一括確定、冪等再試行、書き出し、設定画面からの接続を実装した。[旧 ZIP の事前検査](../lib/features/sync/data/sync_v2_legacy_import.dart) · [取り込みと書き出し](../lib/features/sync/data/sync_v2_archive_service.dart)
- 鍵の形式・アカウントと世代の紐付け・私用鍵の配信・添付・移行・画面を接続した。二台間の実機試験は残っている。
- Windows で Flutter テスト496件と静的解析が通過した。テスト用転送先での確認であり、iCloud 接続、iPad の生体認証・QR 登録、実アーカイブの復元は未検証。
- iCloud 接続用の Dart と iOS のブリッジを追加した。登録済みアカウントと現在の iCloud アカウントを照合し、専用ゾーンで暗号化ヘッダーのページ取得、本文アセットの取得、再送可能な作成を行う。変更トークンが失効した場合は、保存済みの受信箱を維持して最初のページから読み直す。Dart のチャンネル試験を実施した。iOS のビルドと、アプリ画面からの接続は未検証。[iCloud 接続](../lib/features/sync/data/sync_v2_icloud_transport.dart) · [iOS ブリッジ](../ios/Runner/AppDelegate.swift)
- 実装の節目で、決めた方式、検証結果、残っている課題をこの文書と関連する設計メモに反映する。

## 2026-11-15 の接続前検証

- [メモの読み書き](../lib/features/sync/data/sync_v2_note_repository.dart)を追加した。受信箱の暗号文を正本として、現在の版と競合する版を読み取る。編集と送信キューは同じ DB トランザクションで確定する。編集時に見ていた全ての親 ID が現在の版と一致しない場合、親が未取得の場合、比較する本文が未取得の場合は保存しない。同じ変更 ID の再試行は本文と親を照合し、元の暗号文を再利用する。
- プロファイル鍵は呼び出し中だけ借り、リポジトリには保持しない。生の鍵ではなく、認証済みラップから得た世代・プロファイル ID 付きの解除情報を受け取り、新規メモや削除後の書き戻しでも別プロファイルの鍵を拒否する。鍵なしの読み取りは変更 ID と取得状態だけを返し、本文を復号しない。不正な親や循環を持つメモが、別メモの履歴判定を止めないことを検証する。取得待ちの版を画面へ反映する場合は `canCompareVersions` を確認し、未取得・ロック中を削除済みや空の本文に変換しない。
- [世代登録と復旧](../lib/features/sync/data/sync_v2_generation_registration.dart)を追加した。初期の空の世代を作る際、専用の `metadata-v1` ゾーンに固定 ID `active-generation-v1` の暗号化登録情報を作成専用で保存する。別の世代による上書きは拒否する。読み戻し・復号・前後のアカウント照合が成功してから端末内の登録を確定する。二台が同時に作成すると負けた側に空のゾーンが残る可能性があるが、利用する世代は固定の登録情報で決まる。
- 同期用復旧コードにはアカウント、世代、同期鍵を含める。通常プロファイル鍵は同期鍵と管理者鍵でそれぞれラップし、登録情報の中へ暗号化保存する。復旧コードには管理者鍵を含めない。クラウド送信前に世代・同期鍵・同じ登録暗号文をセキュアストレージへ保存し、読み戻しで永続化を確認する。登録途中で終了しても `resumePending()` で同じ登録を再開し、クラウド照合後に端末内の確定と保留情報の削除を行う。クラウドから利用者がデータを削除した場合は専用エラーを返し、自動的な再作成は行わない。復旧コードの利用者による保存確認、管理者鍵の独立したバックアップ・端末認証付き保存・QR 登録は画面接続の工程であり、現在のサービスを画面から自動的に呼び出さない。
- 変更ヘッダーは `v: 1, kind: change`、本文は暗号化された `v: 1, kind: note, body: ...` とした。私用プロファイル鍵のポータブル形式にも版と Argon2id の設定を明記し、未知の設定を拒否する。以前の実験用の版番号がない v2 レコードは受け入れない。実験は新しい `dev_` 世代でやり直し、旧同期や ZIP のデータを消さない。
- テスト用の二端末で、ロック中の受信、正しい鍵だけでの本文取得、同時編集、削除との競合、全親を指定した解決、未取得の履歴、同じ変更の再試行、再起動、DB に本文が平文で残らないことを確認する。[メモの結合テスト](../test/sync_v2_note_repository_test.dart) · [登録テスト](../test/sync_v2_generation_registration_test.dart)
- 実 CloudKit の結合テストに、登録・復旧コードでの二台目参加・暗号化メモの送受信・解除後の読み取りを追加した。二端末相当の独立したストアを同じ iOS 実機プロセスで使う試験であり、二台の物理端末での試験の代替ではない。登録情報は指定した `${devGeneration}_registry` ゾーン、メモは `${devGeneration}_g_<乱数>` ゾーンに限定し、製品用の `metadata-v1` には触れない。指定値は `dev_` に続く1〜30文字の英数字・`_`・`-` とする。

この接続前検証の時点では画面等が未接続だった。現在は上記の iCloud 初版の利用フローへ接続している。履歴判定はメモリ上で世代の全ヘッダーを扱う。チャンクの保存・取得は一括 API で一度だけヘッダーを復号するが、大量データ向けの暗号化索引・期間別ページ取得と、実機での速度・メモリ測定は残っている。

この変更後、Windows ホストで Flutter の単体・ウィジェットテスト572件、静的解析、Dart整形193ファイル、production Webビルドが通過した。Opusによる方式相談と独立レビューを行い、別プロファイル鍵の誤用、登録途中の鍵喪失、実機試験の名前空間、クラウド削除後の自動再作成の4点を修正して再確認した。実 CloudKit の結合テストは、このホストでは iOS のビルド・実行ができないため未実施。二台の物理端末による検証も未実施。

登録の同時作成で負けた端末は、勝った世代の復旧コードを画面から入力する。クラウドを照合して端末内の登録を確定できた後にだけ、同じアカウントの保留登録を整理する。未確認の保留情報を無条件に削除する操作は用意しない。

## ブラウザでの CloudKit Development 確認

CloudKit Console でコンテナ `iCloud.org.ruhenheim.himemo` の Development 環境を開く。スキーマで確認する v2 のレコード型は `HiMemoSyncV2Change`、フィールドは `encryptedHeader`（String）と `encryptedPayload`（Asset、削除記録では省略）。検証用アカウントと世代を登録した開発ビルドが、private database の `HiMemoSyncV2-<generationId>` に書き込む。

ブラウザは開発環境のスキーマと、閲覧権限があるレコードの確認に使う。iPad のアカウント照合、差分トークン、ロック中の受信、解除後の表示は Development に接続した開発ビルドで確認する。接続先は署名時の CloudKit 環境 entitlement で決まるため、試験前に実機ビルドの署名設定を確認する。

Chrome で上記コンテナの Development の Record Types を確認した時点では、v2 の型は未作成。Development は初回保存時に未定義の型とフィールドを作成できる。定義済みフィールドの型の不一致は自動修正されない。初回保存後に Console で型とフィールドを照合する。TestFlight は Production に接続するため、v2 を有効にしたビルドで試験する前に、検証済みのスキーマを Production へ配備する。同期設定 UI の整理は既存方式のブランチで先に確認する。

2026-11-10 に Console から `HiMemoSyncV2Change` を追加し、Production への配備成功を確認した。追加は `encryptedHeader`（String）と `encryptedPayload`（Asset）の新規型のみ。既存型とインデックスは差分なし。v2 は private database のみを使うため、新規型への公開データベースの既定の権限は外した。アプリからの書き込みと端末間同期は未確認。登録情報などで別の型が必要になった場合は別途配備する。

端末の登録情報は、アカウント・世代・同期鍵を一組でセキュアストレージに保存する。受信時は認証済みヘッダーと本文取得待ちを差分トークンと同時に確定し、本文取得が中断されても再開できる。同期セッションはプロファイル鍵に触れず、ヘッダー受信、暗号化本文の取得、送信をそれぞれ上限付きで進める。実機疎通テストでは合成データ用の登録情報を注入する。実際の端末登録 UI や解除後のメモ反映にはまだ接続していない。

macOS の Xcode と Development 署名を使える環境では、未使用の `dev_` 世代を指定して疎通テストを起動する。テストは合成メモを一件だけ書き込み、同一内容を再送した後、差分から一件だけ取得でき、本文を復号できることを確認する。ブラウザで確認できるよう、検証ゾーンと暗号化レコードは残す。疎通テストはアプリ画面での移行や二端末間の解除試験とは別に実行する。

```sh
flutter test integration_test/sync_v2_cloudkit_dev_test.dart -d <iPad-device-id> --dart-define=HIMEMO_SYNC_V2_DEV_GENERATION=dev_<unused-id>
```

手元に Xcode がない場合の実機確認は GitHub Actions で作った TestFlight ビルドを使う。上記の Development 用テストをそのまま実行する手順とは分ける。TestFlight で v2 の疎通だけを先に確認する場合は、既存同期から独立した検証用世代に合成データだけを送受信し、旧版のゾーンや利用者のメモには触れない。通常の同期を有効化する前に、端末登録、鍵の復旧、ロック解除時の反映、二台間での差分取得を別途検証する。

[CloudKit Console](https://icloud.developer.apple.com/dashboard/) · [Apple の環境設定](https://developer.apple.com/documentation/cloudkit/ckcontainer?changes=l_5)

## 受信障害の隔離と再試行

ヘッダーを復号できない記録は、ID・理由・暗号化ヘッダーを隔離領域へ保存する。有効な記録と隔離情報と差分カーソルは同じトランザクションで確定する。内容の異なる同一 ID は既存の有効な記録を保持し、後から来た記録を隔離する。ローカル DB の書き込み失敗ではカーソルを進めない。

本文のダイジェスト不一致やサイズ違反は自動取得から外す。一時的な本文・個別ヘッダーの取得失敗は、30秒から指数的に間隔を広げ、最大5回まで試す。その後は理由を残したまま隔離し、修復後の明示的な再試行に備える。隔離した本文も取得待ちの参照を保持する。CloudKit上の物理削除は同期ログの欠損として記録し、ノートを削除する操作には変換しない。

ヘッダー受信、本文受信、送信はそれぞれ実行し、一つの失敗で後続の送信を止めない。セッションの返り値は各処理の件数と失敗した段階を伝える。自動処理から外れた記録の一覧は、端末内の隔離情報から確認する。隔離の表示・修復 UI は v2 の通常利用を有効にする前に接続する。

## EGM レビューを踏まえた初版の条件

- iCloud から先に検証する。v2 専用の CloudKit レコードゾーンで変更トークンを使い、ヘッダーと本文アセットを分けて取得する。トークンは変更記録と取得待ち参照をローカルに保存した後に進める。失効時はページ単位で再走査する。旧版の履歴整理と添付削除が v2 に届かないことを実機で確認する。Google Drive には同じ変更規則を適用し、差分取得と初回列挙の境界は別に検証する。
- 変更は親 ID を参照する。親がまだ届いていない変更は保留する。同時編集と削除対編集では両方の版を保持する。競合解決は比較した全ての親 ID を参照する新しい変更にする。内容の異なる同一変更 ID は受け入れない。親子逆順、応答消失、途中終了を繰り返しても、最終状態が一致し、削除済みの内容が勝手に復活しないことを確認する。
- 同期鍵の準備と、プライベートプロファイルの復旧・解除を分ける。通常メモにも端末間で復旧できる鍵が必要。新端末、再インストール、クラウドアカウント変更、全端末喪失時について、鍵をどう復旧できるかを実装前に決める。同期鍵を持つ端末でも、プロファイル鍵なしで私用本文を開けないことを検証する。
- 復元の初期公開は一つの世代に限り、確定前のデータは別端末から見えないようにする。二台からの同時初期化と途中終了を試す。旧領域と ZIP は、新領域の別端末復元まで保持する。
