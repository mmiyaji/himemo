# 同期の整合性と保護方式の設計

## 完全削除と資格情報の同期

同期対象のノートを完全削除すると、本文と添付参照を消し、削除済みIDを既存の削除レコードで同期する。更新済みの端末は、同じIDを持つ更新を後から受け取っても削除を維持する。削除レコードは、長期間オフラインだった端末が戻る場合にも使うため、期限で消さない。同期対象外のノートはローカルで削除する。

資格情報の更新には単調増加する版を付ける。版のない既存データは版0として読む。既に鍵ラップを持つ端末は、より新しい版だけを取り込む。資格情報だけの変更も同期キューに入れ、送った版がまだ現行の場合だけ同期済みにする。同じ版で内容の異なる同時変更は自動選択せず、各端末の資格情報を保つ。全端末の収束には、片方でさらに新しい版へ更新する手順、または競合解決UIが必要になる。

更新前のアプリには上記の受信側保護がない。旧端末が既に持つ鍵ラップや過去のバックアップを失効させるには、鍵の更新とデータの再暗号化が必要になる。

## 短いPIN

短いPINは対応端末内の解除に使う。プロファイルのデータキーはランダムに生成し、新しい端末への移行や復旧には十分に長いパスフレーズ、またはランダムな復旧キーを要求する。カメラで読み取るQRコードは、復旧キーまたは認証済みの端末間ペアリングを運ぶ。短いPIN由来の検証値や鍵ラップはクラウドに出さない。

登録済みの端末では、利用者が同じPINを端末ごとに設定できる。1つのPINを複数プロファイルに設定した端末では、一致するプロファイルをまとめて解除する。新規端末は復旧キーまたはペアリングで登録した後にPINを設定する。

端末内のPIN解除には、端末に結び付いた鍵と試行制限を使う。OSが必要な保護を提供できない環境では、プロファイル解除に移行用の資格情報を使う。Webのアプリロックはブラウザ内の画面保護として扱う。短いPINをローカルの起動要素として扱う考え方は [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html#activation-secrets) を参照。

移行は既存の資格情報で解除済みのプロファイルから始める。復旧手段の登録と再解除を確認し、新しい鍵ラップを同期してから旧方式を終了する。過去のバックアップに旧ラップが残る場合、そのコピーには従来の保護が残る。旧ラップを入手した相手による現在のデータの解読まで防ぐには、鍵を更新し、現行データを再暗号化する移行が必要になる。旧バックアップのインポートは専用の導線で扱う。

## iOSの共有

App Groupの共有コンテナに、共有1件ごとのIDを持つディレクトリを作る。添付の書き込みを済ませた後、マニフェストを原子的に公開する。アプリは確定済みのマニフェストを作成順に読む。 [AppleのApp Groups設定](https://developer.apple.com/documentation/xcode/configuring-app-groups)

ノート保存まで共有元のデータを保持し、永続化成功後にIDを指定して受領確認を返す。同じIDで再試行しても重複ノートを作らないよう、共有IDと保存したノートを結び付ける。既存の単一保留ファイルも同じ経路に取り込み、保存成功後に削除する。添付の整理は該当共有IDのディレクトリに限定する。

実機では、未起動時の連続共有、添付付き共有、読み出し後の強制終了、保存後かつ受領確認前の強制終了、旧保留ファイルからの移行を確認する。

## 実装と実機での確認手順

- iOS と Android の新規 PIN プロファイルは、復旧パスワードも登録する。端末用 PIN の鍵ラップは同期対象から分離し、iOS では端末移行しない Keychain 属性を使う。別端末では復旧パスワードで解除した後に PIN を設定する。復旧パスワードが更新されたら、以前の端末用 PIN の鍵ラップは使用できなくなる。
- 既存の短い PIN は、従来どおり解除してから、設定でプロファイルのパスワードを復旧用のパスワードに変更し、「この端末のPINを設定」を実行する。同期完了後、iCloud と Google Drive のそれぞれで別端末から復旧パスワードを使って解除できることを確認する。同じ PIN を2つのプロファイルに登録した端末では、両方が開き、再ロックで両方が閉じることを確認する。
- 過去のスナップショットにある旧 PIN の鍵ラップを無効化する鍵更新と再暗号化、QR による復旧は今回の変更に含めない。プロファイルのパスワード変更は、既存のデータキーを復旧パスワードで包み直す。
- 旧アプリで添付付き共有を保留したまま上書きインストールし、初回起動時に取り込めることを確認する。更新後に HiMemo が閉じた状態で2件以上共有し、手動起動でも順に表示されることを確認する。共有画面を閉じて再度開いた場合や、保存後に受領確認前で中断した場合は、共有内容が残り、同じノートが重複しないことを確認する。
