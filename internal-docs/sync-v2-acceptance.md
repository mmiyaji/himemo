# iCloud v2 初版の受け入れ手順

コードとテスト用転送先の検証と、実機・実クラウドの検証を区別する。Windows アプリは対象外。iOS の署名・ビルド・配布は既存のリリース手順に従い、ここでは実行済みと扱わない。

## 自動チェック

```powershell
dart format --output=none --set-exit-if-changed lib test integration_test patrol_test test_driver
flutter analyze --no-pub
flutter test --no-pub --concurrency=2
flutter build web --no-pub --no-wasm-dry-run -t lib/main_production.dart
```

KDF の設定を弱めず、テストの並列度は CI と同じ2を使う。大きなテスト群と別の Flutter ビルドを同時に実行しない。

## 二台の物理端末・通常画面（未実施）

1. 両端末で旧データを ZIP に書き出し、そのまま保持する。新規登録は一台だけで行い、SYNC/ADMINコードを別々に保管する。コード保存中のアプリ切り替えと、登録途中の終了・再起動を試す。
2. もう一台を SYNC コードで参加させ、通常メモを送受信する。ADMIN コードとその端末用の管理パスワードを設定する。誤ったコード、異なるアカウント、取消しを拒否することを確認する。
3. 同じパスワードの私用プロファイルを二つ、異なるパスワードを一つ作る。一度の入力で一致する二つだけが開き、名前と本文がロック時に見えなくなることを確認する。管理者モードの終了、画面退出、ホーム画面・アプリ切り替え、復帰時の再ロックとネイティブのスナップショット保護を確認する。
4. 同時編集、削除との競合、同時のパスワード変更を作り、片方を自動で上書きしないことと、画面からの明示的な解決後に一致することを確認する。
5. 写真・動画・音声・ファイルを送受信する。途中の通信切断、再起動、隔離と再試行、欠損チャンクを試す。iOSのファイル選択・保存で非アクティブになる場合、機密内容が隠れ、取消し・中断が分かることを確認する。
6. 旧 ZIP の通常・私用の復元先と添付欠落の確認を行う。同じ ZIP の二度目で増えず、途中終了で一部だけ公開されないことを確認する。ブロック付きメモを編集・添付削除後に書き出して、旧形式でも更新後の内容を読めることを照合する。
7. ウィジェット・共有から通常プロファイルへ保存し、確認応答失敗後の再送で重複・編集上書き・削除復活がないことを確認する。旧 DB に新しい v2 メモを書かないことを確認する。
8. オフライン起動と再接続、iCloud アカウント変更、データ削除、同時初期登録に負けた端末の復旧、旧メモへ戻った際の同期先復元を確認する。

管理者認証は生体認証を標準とし、パスワードは任意方式（6文字以上）とする。QR ペアリング、Web/Google Drive v2、長期索引・履歴圧縮を検証済みと扱わない。大容量・複数年データでの初期同期時間、メモリ、KDFの応答時間も実機で測る。


## 生体認証と登録失敗の再試行（実機未実施）

- 初回をFace ID／Touch IDで作成し、管理パスワードなしで登録、ADMINコードを保管。生体認証の取消し、ロックアウト、未登録端末、アプリ切替で権限が残らないことを確認する。
- 二台目はSYNCで参加後、ADMINコードからその端末の生体認証を設定する。Face ID再登録・指紋追加後はADMINコードで復旧する。
- パスワード方式を選ぶ場合は管理者用6文字で登録できる。旧12文字以上の既存パスワードも利用でき、解除後に生体認証を有効化できる。私用パスワードの条件は今回変更しない。
- 通信を切って登録失敗を起こし、保留の再開で同じ世代を使う。エラーの診断コードは処理名と固定エラーコードだけとし、復旧コード・鍵・アカウント・本文を含めない。


## ZIPインポートの復元先（実機未実施）

- 通常メモと私用3グループを含むZIPを、私用プロファイル未作成のv2へ取り込む。確認画面で復元先がない理由が分かり、ZIPを選び直さず管理者認証・復元先の作成・各グループへの割り当てを完了できることを確認する。
- 作成済みの私用プロファイルをロックしてから同じZIPを開き、確認画面内で解除できることを確認する。ファイル選択中にアプリを切り替えて再ロックされた場合も同様に操作できることを確認する。
- 生体認証・入力のキャンセルでインポートを確定しないこと、同じ復元先へ複数グループを割り当てられないこと、未連携添付の確認と全復元先の割り当てが済むまで取り込めないことを確認する。
- 実際のバックグラウンド移行では画面と解除情報を破棄し、戻っても勝手にインポート・作成を続行しないことを確認する。


## 管理者による一括復元・上書き（実機未実施）

- 私用プロファイルがない状態でZIP確認画面を開き、「管理者として一括復元・上書き」を実行する。管理者認証以外のパスワード・復元先選択・添付同意を要求せず、通常と私用3グループが復元されることを確認する。
- 同じZIPを再度取り込んでも増えず、ローカル編集・削除・既知の競合がZIPの内容へ戻ることを確認する。変更したZIPの同じ元IDも重複せず更新され、ZIPにないメモは残ることを確認する。
- 二台目が同期とADMINコードで自動作成された私用プロファイルを開けること、個別パスワードを後から設定できることを確認する。
- 管理者解除をしていないAPI呼び出し、認証キャンセル・実バックグラウンド・破損ZIPでは一部のプロファイルやメモだけが公開されないことを確認する。


## 設定の管理者モードからのZIP取り込み（実機未実施）

- v2登録済み端末で設定の管理者モードに入り、v2画面からZIPを選び、一括復元・上書きを実行する。通常・私用の手動割り当てや個別パスワードなしで取り込めることを確認する。
- 旧ビルドから更新した端末では初回のみv2生体認証等で連携し、次回から設定の管理者モードを利用できることを確認する。端末補助鍵の保存失敗時も従来のv2認証は成功すること。
- ZIP選択の一時的なinactiveとresumedの順序を変えても取り込めること。実際のアプリ切り替え・hidden/pausedでは権限と遅れた選択が破棄されること。
- 管理者モードを終了した場合、解除の途中で終了・再認証した場合、SYNCだけで参加した端末では補助鍵から解除できないこと。
- 同じ端末の再インストール後にSYNCだけで参加しても、旧Keychain項目から管理者権限が復活しないこと。ADMINコード等による新たな管理者登録は可能であること。
- 設定モードによる解除からはADMINコードを書き出せず、生体認証の新規登録もできないこと。従来のv2管理者認証後は実行できること。


## QRによる端末追加（実機未実施）

1. 一台目のv2メニュー「他の端末をQRで追加」で同期用QRを表示し、二台目の「QRを読み取って参加」で読み取り、確認後に同じiCloudアカウントで参加する。通常メモが同期し、この段階では管理者権限が付かないこと。
2. 必要な場合だけ、一台目でv2管理者認証後に「管理者登録用QRを表示」、二台目のメニュー「管理者登録用QRを読み取る」で生体認証を設定し、私用メモも確認する。設定だけの管理者セッションからADMIN QRを出せないこと。
3. SYNC/ADMINの取り違え、無関係なQR、破損・巨大な入力、異なるアカウント・世代を拒否すること。読み取り連続通知でも一度だけ確定し、取消しで登録しないこと。
4. 初回のカメラ権限許可・拒否・設定からの再許可、inactive/resumed、実際のアプリ切替・復帰で、秘密のQRが残らずキャンセル後の遅い結果が採用されないこと。
5. iPhone縦・iPad横・大きな文字でQRが読み取れるサイズを保ち、スクロールと閉じる操作が可能なこと。両端末の旧データを保持して確認する。

このQRは復旧コードそのものであり、有効期限付きの一時ペアリングとは区別する。QRの写真・スクリーンショットも秘密情報として扱う。
