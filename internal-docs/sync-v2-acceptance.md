## 1. 配布しないiOSビルド・起動確認

登録済みの `iOS TestFlight` を `verification_only=true` で実行し、検証専用の `.github/workflows/ios-verify.yml`（`iOS Verification`）を呼び出す。新規workflowは既定ブランチに存在せず手動起動できない場合があるため、この入口を使う。Xcode 27.1の既存 `xcode-27` runnerを使用する。署名資材の登録、IPA作成、TestFlightアップロード、実CloudKit試験は含まない。`verification_only=true` は他の入力より優先され、署名・アップロード・配布jobはすべてskipする。これを省略した既存TestFlight workflowは既定でアップロードするので、この確認には使わない。

```sh
gh workflow run ios-testflight.yml --ref feature/v2-on-v1-ui --field verification_only=true --field upload_to_testflight=false
```

未pushの変更はGitHubから検証できない。pushとworkflowの実行はユーザーの許可後に行う。workflowファイルがブランチに反映済みであることを確認する。

- 検証対象のHEAD SHAとrun URLを記録する。
- 無署名のsimulator buildが成功すること。
- 新規simulatorでproduction起動の初回画面が表示されること。
- network／privacy channelとQuick Lookのopen→closeが正常に応答すること。
- artifact `ios-verification-<run-number>` 内の `source-commit.txt`、起動ログ、テスト結果、画面証拠を確認する。
- 完了後も「実CloudKit・生体認証・カメラ・実機メディア再生は未検証」のままとする。

## 2. Development署名の実機・合成データ試験

Macで、対象端末のiCloudログインとDevelopmentのCloudKit権限を確認する。新しい `dev_` 名前空間だけを使う。テストはそのCloudKitゾーンに合成レコードを作成するため、実行先と署名環境を先に確認する。製品の登録先 `metadata-v1` は使わない。名前空間の分離はDevelopment署名の代替ではない。

```sh
flutter pub get
flutter gen-l10n
flutter devices
DEVICE_ID="<flutter devicesで確認した実端末ID>"
GENERATION="dev_$(date -u +%Y%m%d_%H%M%S)_$(openssl rand -hex 3)"
flutter test integration_test/sync_v2_cloudkit_dev_test.dart -d "$DEVICE_ID" --dart-define=HIMEMO_SYNC_V2_DEV_GENERATION="$GENERATION"
flutter test integration_test/sync_v2_key_performance_test.dart -d "$DEVICE_ID"
```

`GENERATION` は毎回新しくする。無指定ではCloudKit試験がskipされるため、コマンド終了コードだけで成功とせず、対象テストが実行・成功したことを確認する。Flutterコマンドは順番に実行する。

CloudKit試験は1プロセスに二端末相当の独立ストアを作り、登録・復旧、通常／私用メモ、1MiB超の添付、ロック中の非開示、解除後の完全一致を検証する。二台の物理端末、カメラ、生体認証の代替ではない。使用したテストゾーンは記録し、自動でクラウドを整理・削除しない。

## 3. 二台の物理端末での通常操作

同じテスト用iCloudアカウントの端末A/Bで、同じビルドを使う。以下はすべて未実施。

### 初回設定・端末追加・復旧

- [ ] Aの「同期とセキュリティ」で初回設定。保管確認前は登録を確定できず、取消しで未登録の鍵が片付く。
- [ ] 端末ごとに生体認証／管理パスコードを選べる。管理パスコードは4文字以上で端末ローカルに保存される。
- [ ] 通常の端末追加QRはSYNC＋ADMINの一つ。Bで読み取り・確認し、通常メモが同期する。B自身の管理者解除方式を設定できる。
- [ ] 復元ファイル `himemo-recovery.json` の保存と読み込みで再登録できる。秘密を含むQR・ファイル・画面キャプチャを通常ログやartifactへ添付しない。
- [ ] 詳細設定のSYNC-onlyで参加した端末には管理者権限が付かない。プロファイルのパスコードによる解除はできる。
- [ ] 不正QR／ファイル、別アカウント、別世代、不正ADMIN、取消しを拒否し、登録や権限が残らない。
- [ ] 通信切断・公開後の端末登録失敗・再起動から同じ保留設定を再開できる。

### パスコード・管理者・ロック

- [ ] 同じ4文字以上のパスコードのプロファイル二つと、異なるもの一つを作る。一度の入力で一致する二つだけが開く。
- [ ] プロファイル同士の重複は許可し、管理パスコードとの重複は設定・作成・変更時に拒否する。
- [ ] 誤入力1〜4回は待機なし、5回30秒、6回1分、7回5分、8回15分、9回以降1時間。プロファイル／管理パスコードで待ち時間が共有される。
- [ ] 管理者は全プロファイルを開き、名前変更・削除・パスコード変更が可能。競合／未受信データがある削除は中止する。
- [ ] ADMIN鍵のQR・復元ファイルや解除方式の管理には、ADMINを直接解除したセッションが必要。
- [ ] ロック、管理者終了、ホームへ移動、アプリ切替・復帰で本文・添付・検索内容を隠す。解除処理の実行中／待機中にロックしても後から開かない。
- [ ] 保存準備中や遅延プレビュー中にロックしても平文が戻らない。ゴミ箱のメモがプレビュー到着で復活しない。
- [ ] 生体認証の取消し・ロックアウト・鍵無効化から管理者権限が残らない。「QR・ファイルから管理者権限を復元」が使える。
- [ ] 再インストール後のSYNC-only参加で、旧Keychain項目から管理者権限が復活しない。

### 同期・競合・通信障害

- [ ] 一覧・編集・検索・カレンダー・インサイト・ゴミ箱を通常UIで操作できる。
- [ ] 通常は自動同期。「今すぐ同期」、失敗後は「同期を再試行」、一覧の下方向スワイプで再試行できる。
- [ ] 同時編集と削除の競合を作り、勝手に上書きしない。「残す版を選ぶ」で全headを消費して一致する。
- [ ] 本文・親が未受信なら競合を解決できず、確認後にheadが増えた場合は再確認を求める。
- [ ] 期限切れのゴミ箱メモが競合中でも、他のメモが一覧から消えず、競合を解消できる。
- [ ] 同期受信とタグ一括変更・アーカイブを重ねても、新着メモが削除されない。
- [ ] オフライン起動→再接続、通信中断、iCloudサインアウト／アカウント変更、クラウドデータ削除、同時初回登録への対処が分かる。

### 添付・端末連携・表示

- [ ] 写真・動画・音声・ファイルの追加、再生／表示、編集、削除、Bでの復元を確認する。
- [ ] 8MiB以上の添付で通信中断・再起動・未着チャンク・再試行を確認する。破損データを表示しない。
- [ ] ロック／バックグラウンドで写真・再生・Quick Lookを閉じ、一時ファイルが片付く。ファイル選択・共有・認証の一時inactiveも確認する。
- [ ] ウィジェット・共有から通常プロファイルへ保存。確認応答失敗後の再送で重複、編集上書き、削除復活を起こさない。
- [ ] iPhone縦／横、iPad横・分割表示、大きな文字、キーボード表示で作成・編集・設定・QRを操作できる。

## 4. 実機release性能

- [ ] 1/3/10プロファイル解除の時間・イベントループ遅延・メモリを記録する。KDFは19MiB/t2/p1を維持する。
- [ ] 履歴を増やし、初回索引構築と通常の再読出しを分けて計測する。
- [ ] 8MiB以上の添付の保存・読出しと、その間の一覧・別DB操作の待ち時間、メモリを計測する。

ホストdebugでは8MiB添付時に別DB操作が約2秒待った。実機releaseで操作性を評価し、許容できなければ改善して再試験する。ホストの値を実機の合格値にしない。

## 結果の記録

各項目に、確認日・コミットSHA・run URL／ビルド番号・端末・OS・署名環境・成功/失敗/未実施・再現手順を添える。秘密情報は含めない。失敗は修正後に対象を再試験する。全体の受入完了とTestFlight配布は別判断とし、この手順の作成やsimulator成功だけで配布済み／実機合格としない。
