# V2 Webストレージ復旧控え（開発用）

移行中断などでWeb V2のDBを開けなくなった際、旧コピーと新コピーを変更せずに確認・書き出すための独立した開発用画面です。通常のアプリからはリンクされず、復旧・統合作業の完成を意味しません。

- `tools/v2_web_recovery.dart` を明示的にWebビルドし、対象V2アプリと **同じorigin（スキーム・ホスト・ポート）** で開きます。異なるoriginではブラウザーの保存領域が異なるため、対象データは見えません。実運用のoriginへ配置する場合は既存ファイルを上書きしない専用パスを使います。
- ビルド時は専用パスの `--base-href` と `--pwa-strategy=none` を指定し、既存アプリのサービスワーカーやキャッシュと混同しないようにします。
- V2を開いている他のタブを閉じてから確認します。画面はV2と同じWeb Lockを取得できない場合、コピーの取得や書き出しを拒否します。
- 旧localStorage、旧IndexedDB、新Wasm IndexedDB、新OPFSについて存在とバイト数を表示します。環境が保存先の検出・読み出しに対応しない場合は「確認できません」と表示し、「存在しない」とは扱いません。
- 「書き出す」は利用者が選択したSQLiteコピーをダウンロードするだけで、DB、旧コピー、移行マーカーを削除・上書きしません。検査とダウンロードのたびにロックを取得します。
- 出力は暗号化されたV2データベースの控えで、通常のメモZIPではありません。アプリへの直接インポート機能や、自動復旧・統合機能はありません。復旧コード・管理者コード・パスワード・本文の入力や表示は行いません。
- Web Locks、IndexedDBの一覧取得や、該当するWasm保存先が使えない環境では対応するコピーを読み出せません。初期化が中断したDBの自動削除や、どのコピーが新しいかの自動判定はしません。

自動試験は専用のブラウザーoriginとデータを使います。`test_driver/sync_v2_web_storage_probe.dart` と本ツールを同じoriginの異なるパスへビルドし、`playwright/v2-recovery.config.js` を実行します。
