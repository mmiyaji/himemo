# Sync v2 性能確認（2026-11-18）

開発ホスト Windows / Flutter debug VM の単発計測。iOS実機・releaseの性能値や受入基準ではない。Windowsネイティブアプリは起動していない。

## 一覧の履歴走査

`SyncV2Inbox` schema v4に以下を追加した。

- generation・profile・noteをドメイン分離したHMAC-SHA256の索引。平文IDや鍵は保存しない。
- 親レコードIDの依存表。親の後着や変更時に依存ノートの状態を無効化する。
- generation・profile・note tokenをAADに含む、暗号化した最新head/pending状態。
- 鍵なしのDB更新で未索引履歴を記録する表。初回の読出し時に与えられたSYNC鍵で認証して構築する。

読出しはプロファイル内の状態を参照し、変更があったノートだけ元のresolverで再構築する。本文の到着状況はその都度確認する。保存・CAS・競合解消は全履歴を認証する既存経路を維持する。

600履歴・対象10ノートの比較では、headerの復号が600回から10回へ減少。観測時間は55.2msから2.0ms（約27.5倍）。固定時間をテストの成功条件にはしていない。追加の20添付ノートも、正常な履歴ならprefix外の再復号を避ける。依存無効化のUPDATEはEXPLAINで主キー3列の利用を確認した。

初回索引構築、変更ノートの再構築、prefix外の不正・循環履歴には走査が残る。不正な対象履歴は従来どおり失敗させる。同一ノートの古い暗号化状態を戻すなど、ローカルDB自体を改ざんする攻撃に対する単調性の証明はない。一覧表示を欺けても更新は既存の全履歴CASで照合する。他ノート・プロファイル間の状態差替えはAADで拒否する。

## パスコード解除

既存のnative `compute()`でArgon2idをIsolateに分離済み。m=19MiB、t=2、p=1と逐次解除を維持した。プロファイルの並列数を増やしてメモリを増大させる変更はしない。

| プロファイル数 | 解除時間 | イベントループ最大間隔 |
|---|---:|---:|
| 1 | 118ms | 18ms |
| 3 | 337ms | 17ms |
| 10 | 1318ms | 18ms |

実際の鍵の回収と誤パスコード拒否も確認する。計測外で鍵レコードを作り、解除部分だけを測定した。

## 大きい添付

実ファイルSQLiteと実暗号化で8MiB・8チャンクを保存・復元し、全バイトの一致を確認した。暗号処理の開始時に同一inboxへの別操作を外側Zoneから投入し、同じトランザクション内の再入読出しを測らないようにした。

| 操作 | 全体 | 別inbox読出しの待機 |
|---|---:|---:|
| idle読出し | 0.9ms | — |
| 添付保存 | 2073ms | 1742ms |
| 添付読出し | 2109ms | 2036ms |

待機はDBキューとイベントループ遅延を含む。debug時のイベントループ最大間隔は約300ms。添付処理の原子性・ロック検査を変更する最適化は今回行っていない。保存・復元中には別DB操作が待つ制約があり、iOS実機releaseでの測定を引き続き受入項目とする。
