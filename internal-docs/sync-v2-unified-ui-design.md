# Sync v2: v1 UI 統合と鍵モデル整理 設計方針

作成日: 2026-11-17 / 対象ブランチ: `feature/v2-on-v1-ui`

## 0. 前提

- 過去データ（v1 ローカルDB・Google Drive 同期・v1 アーカイブ）は **すべて破棄してよい**。移行処理は作らない。
- アプリは **自分専用のメモ**。ただし共有端末に入れる使い方は許容する。
- 隠しコンセプト: プロファイルごとのパスコードで中身を使い分けられる（ダミープロファイル的な使い方が「できる」）。UI でこの用途を前面に出さない。

## 1. 最初のゴール

**v1 の画面導線のまま、v2 のデータを正しく読み書きできること。**

v2 専用ワークスペース画面（`sync_v2_workspace_screen.dart`）は機能が中途半端なため、ノート操作の画面としては使わない。v1 の画面（約47k行）をそのまま使い、データ層だけを v2 に差し替える。

## 2. 鍵モデル

| 層 | 守る相手 | 鍵 | 渡し方 / 解除 | 強さ |
|---|---|---|---|---|
| iCloud アカウント | – | Apple ID | OS | 暗号化済みの箱を置く場所 |
| SYNC 鍵 | 外部（クラウド漏洩） | 自動生成ランダム鍵 | QR / 復元ファイル | **強固（唯一の外部防壁）** |
| ADMIN 鍵 | 端末を触る人 | 自動生成ランダム鍵 | QR / 復元ファイルで端末登録。解除は端末ごとに **生体認証 または 管理パスコード** | 端末ローカルのみ保存 |
| プロファイルのパスコード | 端末を触る人 | ユーザー入力（4桁〜） | 同期される。入力値に一致したプロファイルだけ開く | ゆるくてよい |

原則: **外部からの防御は SYNC 鍵に集約し、端末内のロックはすべて手軽にする。**

### 2.1 プロファイルのパスコード

- 最短 **4文字**（数字4桁を許可）。現行 12文字の制約を撤廃（UI と `SyncV2ProfileKeys._validatePassphrase` の両方）。
- パスコードで包んだプロファイル鍵は、SYNC 鍵＋通常プロファイル鍵でさらに暗号化されて同期される（現行 `SyncV2ProfileCatalog` の構造を維持）。SYNC 鍵を持たない者は総当たりできない。
- 割り切り: SYNC 鍵を持つ者（ペアリング済み端末の取得者・SYNC コード保持者）はオフラインで総当たり可能。パスコードは「使い分けのための軽いロック」と位置づける。
- 解除画面では入力値を全プロファイルに照合し、一致したものだけ開く（現行 `unlockMatching` の動作を維持）。
- 不一致時は「違います」だけを表示し、プロファイル数や存在を示唆しない。
- 誤入力回数に応じた待ち時間（端末ローカル、2.3 参照）。
- 同一パスコードの重複: **許可**。同じパスコードの複数プロファイルは同時に開く（現行動作のまま）。
- Argon2id パラメータ（2.4 参照）。

### 2.2 管理者モード

- ADMIN 鍵があれば全プロファイルを開ける。
- 端末ごとに解除方式を選ぶ: **生体認証** / **管理パスコード（4桁〜）**。共有端末では生体認証をオフにしてパスコードのみ、という運用を可能にする。
- 管理パスコードで包んだ ADMIN 鍵は **端末のキーチェーンのみに保存し、同期しない**（現行 `SyncV2AdminStore` の保存先を維持）。
- **管理者はすべてに優先する**（2026-11-18 決定）。設定画面経由（端末認証＋端末に記憶した ADMIN 鍵）の管理者も、プロファイルのパスコード変更・修復ができる。ADMIN 鍵そのものの管理（生体認証の登録、管理者 QR）だけは、ADMIN 鍵を直接解除したセッションに限る。
- 管理パスコードはどのプロファイルのパスコードとも一致させない（作成・変更時に検査）。プロファイル同士の重複は許可するが、管理パスコードとの重複だけは禁止する。
- 誤入力時の待ち時間はプロファイルと共通の仕組み。
- 最短長: 現行 6文字 → 4文字。

### 2.3 誤入力時の待ち時間

- 端末ごとに 1 つのカウンタを持ち、プロファイル解除と管理パスコード解除で **共有** する（交互に試して回避されるのを防ぐ）。
- カウンタと次回入力可能時刻はキーチェーン（`unlocked_this_device`）に保存し、アプリ再起動や再インストールでは消えにくくする。時刻は単調時計ではなく保存時刻で判定し、端末時計を戻された場合は待ち時間を延長側に倒す。
- いずれかの解除に成功したらリセット。生体認証による管理者解除の成功でもリセット。

| 連続失敗回数 | 次の入力までの待ち時間 |
|---|---|
| 1〜4 | なし |
| 5 | 30秒 |
| 6 | 1分 |
| 7 | 5分 |
| 8 | 15分 |
| 9 以降 | 1時間（毎回） |

- 待ち時間中も表示は「しばらくしてから再度お試しください」程度とし、どのプロファイルの試行かは示さない。
- データ消去などの破壊的な措置は行わない（ダミー用途で誤入力が起きやすいため）。

**開発用の回避コマンド**

- `AppFlavor.development` のビルドかつ v2 バックエンドに限り、プロファイル解除ダイアログの **タイトルを3秒以内に5回タップ** すると待ち時間とカウンタをリセットする（解除ダイアログにロゴがないためタイトルを使う）。
- production フレーバーではコード上で無効化し、production ビルドの到達性をテストで保証する（フレーバー判定を通らない限りハンドラを登録しない）。
- リセット時は監査ログ（`audit_log.dart`）に記録する。

### 2.4 Argon2id パラメータ

SYNC 鍵が外部への唯一の防壁で、パスコードは 4 桁を許す以上、KDF の強さで総当たりを防ぐことは期待しない。役割は「SYNC 鍵を持つ者による総当たりの手間を最低限増やす」程度とし、解除速度を優先する。

| 対象 | memory | iterations | parallelism | 目安（中位 iPhone） |
|---|---|---|---|---|
| プロファイルのパスコード | 19 MiB | 2 | 1 | 約 100ms / 件 |
| 管理パスコード（端末ローカル） | 19 MiB | 2 | 1 | 約 100ms |

- OWASP の Argon2id 最低推奨値（m=19 MiB, t=2, p=1）に合わせる。現行は 64 MiB / 3 / 4。
- 既存データは破棄してよいため、`formatVersion` を上げ、旧パラメータのレコードは読み込まない（移行処理なし）。
- 解除時はプロファイル数 × 100ms 程度。プロファイルが増えて体感が悪化する場合は、照合を並列化する（Isolate）。

### 2.5 端末追加

- 「端末を追加」は既定で **1種類の QR（SYNC + ADMIN）**。
- 共有端末向けに「管理者なしで追加（SYNC のみ）」を詳細設定に置く。
- 復元コードは 1 ファイルにまとめて出力（SYNC / ADMIN を内包）。

## 3. v1 UI → v2 データ 接続方式

### 3.1 差し替え点

v1 のノート永続化は `NotesController`（`home_providers.dart`）→ `encryptedNoteStoreProvider`（`EncryptedNoteStore`: `save` / `saveOne` / `deleteById` / `deleteByVaultId` / 読み込み）に集約されている。v2 側も同じ `NoteEntry` モデルを使っている（`SyncV2Workspace` が `NoteEntry.fromJson` で復元）。

→ **`EncryptedNoteStore` 相当のインターフェースを v2 実装に差し替える** のを第一手段とする。

```
v1 画面 ─ NotesController ─ NoteStore(interface)
                                ├─ (削除) EncryptedNoteStore … v1 ローカルDB
                                └─ SyncV2NoteStore … SyncV2Workspace / SyncV2NoteRepository
```

- `vaultId` ⇔ v2 `profileId` を 1:1 対応させる（`everyday` = 通常プロファイル）。
- 保存: `SyncV2NoteRepository.save`（`expectedHeadIds` は直前に読んだ head を保持）。
- 削除 / ゴミ箱 / アーカイブ / ピン: v1 の `NoteEntry` フィールド更新として save に載せる。完全削除は `delete`。
- 読み込み: 解除済みプロファイルのノートのみ返す。ロック時は該当 vaultId のノートを state から除去（v1 の `concealPrivateNotes` 相当）。

### 3.2 ロック状態の一本化

v1 のロック系 provider を v2 の状態から導出する形にする。

| v1 provider | v2 での実体 |
|---|---|
| `privateVaultSessionControllerProvider` / `unlockedPrivateProfileVaultIdProvider` | `SyncV2Workspace` の解除済みプライベートプロファイル |
| `adminModeSessionControllerProvider` | `SyncV2Workspace.adminUnlocked` |
| `PrivateProfileUnlockController` | `SyncV2Workspace.unlockPrivate(passcode)` |
| `PrivateMemoProfilesController` | `SyncV2Workspace.profiles` |

これにより「設定画面で管理者解除しても v2 に反映されない」問題は構造的に消える。

### 3.3 添付

`encryptedAttachmentStoreProvider` を `sync_v2_attachment_service` に差し替える（フェーズ3）。

### 3.4 削除対象（最終フェーズ）

- v1 ローカルノート DB（`himemo_notes.sqlite`）と `EncryptedNoteStore`
- Google Drive 同期（`google_drive_sync_transport.dart` ほか）
- `sync_v2_legacy_import.dart`、v1 アーカイブの取り込み・管理者アーカイブ復元
- v2 ワークスペース画面のノート一覧・編集・検索・カレンダー・インサイト・ゴミ箱部分
- v1 独自の管理者モード / プライベートセッション状態

v2 固有の操作（QR ペアリング、復元コード、生体認証登録、プロファイル作成）は v1 の設定画面に「同期とセキュリティ」として集約する。

## 4. 性能

- 現行 `SyncV2NoteRepository.readProfile` は全プロファイルの履歴を毎回走査してから絞り込んでいる。**プロファイル別の最新状態テーブル＋インデックス** を導入し、必要分のみ読む。
- 解除時の KDF はプロファイル数に比例する。パラメータ軽量化で対処。
- 月単位の物理ファイル分割は、上記で不足した場合の手段とする（月跨ぎ検索・暗号化の複雑化を避けるため初期は採用しない）。

## 5. フェーズ

| # | 内容 | 完了条件 |
|---|---|---|
| 1 | `NoteStore` を抽出し、v2 実装をつなぐ（一覧・作成・編集・削除） | v1 画面で通常プロファイルのノートを v2 に保存・再起動後も表示 |
| 2 | ロック状態を v2 に一本化。パスコード 4桁化・重複禁止・誤入力待ち時間 | v1 の解除画面でパスコード一致プロファイルが開く。管理者解除で全プロファイル表示 |

| 5 | 設定画面へ v2 操作を集約、v1 データ層・v2 専用画面の削除 | 旧コード削除後に全テスト通過 |
| 6 | 性能（最新状態テーブル、KDF 調整） | プロファイル数・ノート数を増やしても解除と一覧表示が劣化しない |

## 6. 開発環境と検証方針

- 手元に iOS ビルド環境がないため、**同期をスタブにした状態で一通り実装する**。
  - 既存の `lib/features/sync/testing/sync_v2_local_preview.dart`（`createLocalPreviewController`）を土台に、CloudKit 通信をプロセス内のスタブに置き換えた構成で、Windows / Web（開発用）で v1 画面を動かす。
  - 2 端末間の同期は、同じスタブを共有する 2 つのワークスペースを使った単体・結合テストで確認する。
- Web 版はリリースしない。開発確認用にのみ使う。
- 実機の CloudKit と生体認証は、必要なタイミングで GitHub Actions の iOS ワークフロー（`ios-testflight.yml`）で確認する。

## 7. 決定事項（2026-11-17）

1. プロファイルのパスコードの重複は許可する（管理パスコードとの重複のみ禁止）
2. Argon2id は 2.4 の推奨値を採用
3. 誤入力の待ち時間は 2.3 の推奨値を採用。開発ビルドのみアイコン 5 回タップで回避
4. Web 版はリリースしない。同期スタブで開発し、iOS 実機確認は GitHub Actions で行う

## 8. 実装状況

### フェーズ1（2026-11-17）

- `NoteStore`（`lib/features/home/data/note_store.dart`）を抽出し、`NotesController` は `noteStoreProvider` 経由で保存する。
- v2 実装 `SyncV2NoteStore`（`lib/features/sync/data/sync_v2_note_store.dart`）。ID 変換: v1 `X` ⇔ v2 `note_X`、`everyday` ⇔ v2 通常プロファイル。
- 切り替えは `--dart-define=HIMEMO_NOTE_BACKEND=...`:
  - `v1`（既定）: 従来のローカル暗号化 DB
  - `v2`: iCloud の v2 ワークスペース（登録済みであること）
  - `v2-local`: 同期スタブ。起動時に自動登録。鍵はメモリ上のみで、再起動すると以前のデータは読めない
- v2 のプロファイル解除状態が変わると `NotesController.reloadFromStorage()` を呼ぶ。

```bash
flutter run -t lib/main_development.dart -d chrome --dart-define=HIMEMO_NOTE_BACKEND=v2-local
```

未対応（後続フェーズ）: 添付（参照は空で保存）、v1 のロック UI と v2 解除の接続、v1 同期処理（Google Drive / 旧 iCloud）の停止。

### フェーズ2（2026-11-17、一部）

- 実装済み:
  - パスコードの最短長を 4 文字に（プロファイル・管理パスコード・v1 のプライベート設定）。
  - Argon2id を m=19MiB / t=2 / p=1 に変更し、鍵レコードの `formatVersion` を 3 に上げた（旧レコードは読まない）。
  - 誤入力の待ち時間を 2.3 の値に変更。カウンタはプロファイル解除と管理パスコード解除で共有（`syncV2UnlockAttemptsKey`）。生体認証による管理者解除の成功でもリセット。
  - 開発ビルド限定の回避操作（上記）。
  - v1 の解除ダイアログ → `SyncV2WorkspaceController.unlockPrivate`。一致したプロファイルをまとめて開く。
  - v1 の管理者モード → 端末に記憶した ADMIN 鍵（`unlockAdminFromSettings`）、なければ v2 の生体認証。
  - v1 のロック操作 → v2 のロック（`lockPrivate`）。
- Codex レビューの指摘に対応:
  - 競合中・本文未着のノートは表示するが、保存・削除を拒否（`SyncV2StaleNote`）。競合解決 UI は後続。
  - 同期で受信したノートを v1 一覧に反映（ワークスペースのノート一覧が置き換わったら再読み込み）。
  - v2 バックエンド時は iOS の `/notes` → `/sync-v2` 転送を止める。
- 追加で実装（2026-11-18）:
  - v1 のプロファイル作成 → v2 の `createProfile`。ADMIN 鍵が必要なため、端末認証のあと管理者モードに入ってから作成する（開発用スタブのみ端末認証を省略）。
  - v1 のパスコード変更 → v2 の `changeProfilePassword`。
  - 待ち時間中は「しばらくしてから再度お試しください」と表示（プロファイルの有無は示さない）。
  - Web（`v2-local`）で確認済み: 4 桁パスコードでの作成・解除・ロック、5 回失敗後の待ち時間、開発用の回避操作。
- フェーズ2の残りを実装（2026-11-18）:
  - v1設定画面で、生体認証が無効または端末認証に失敗した場合に管理パスコード入力へ接続。誤入力の待ち時間は既存の共有カウンタを使う。
  - プロファイル作成・パスコード変更・競合修復と、管理パスコードの復元・変更時に重複を検査。検査自体は解除試行回数を変更しない。プロファイル同士の重複は引き続き許可。
  - v1設定画面からv2プロファイルの名前変更・削除へ接続。削除はノートとカタログの削除履歴を同じトランザクションで保存し、競合・未受信データがあれば中止する。
  - 同期受信による名前変更・削除を解除済みプロファイル一覧へ反映（管理者・パスコード解除の両方）。
  - 添付、端末ごとの解除方式の選択、設定画面への同期操作の集約は後続フェーズ。

### フェーズ3（2026-11-18）

- v1のメディア取り込みとビューアを `SyncV2AttachmentStore` で接続。取り込み時は端末内の暗号化された専用領域へ保存し、ノート保存時に対象プロファイルのv2チャンクとして確定する。
- `NoteStore.save/saveOne` は確定したノートを返す。v2の添付参照を状態へ反映し、本文編集でも参照を維持する。チャンクとノートの保存・プロファイル間移動はトランザクション内で処理する。
- 一時添付と下書き本体にもv2の鍵を使用。ロック後の読み出しを拒否し、保存済み下書きを維持したまま不要な一時ファイルを片付ける。
- v1同期はv2バックエンドで無効化。v1 ZIP取り込みも開始前に拒否する（移行処理は作らない）。
- 検証: 全体823件成功、v2専用接続テストも別途成功、静的解析・Webビルド成功。Webで実ファイルの画像・動画・音声の取り込み、保存後の画像表示と動画・音声の再生を確認。iOS実機確認は後続。
- Opusの設計・実装レビュー指摘を反映済み。修正後の再レビューはClaude Codeの利用上限で未実施。大きな添付のDB占有時間の改善はフェーズ6。

### フェーズ4（2026-11-18）

### 2026-11-18: 同期操作の整理（ユーザー指示）
- v1の詳細同期・個別アップロード／ダウンロード／適用／修復という操作体系は引き継がない。v2設定は自動同期の状態と「今すぐ同期」（失敗時「同期を再試行」）、別端末の追加用QR、復元用ファイルの保存、端末内の管理者解除方式に整理。
